### 2 · Purpose & Vision

The repository already proves a *hello-world* DevOps path (containerised API Gateway + CI handshake). Phase 2 will evolve it into a **full micro-service sandbox** that hiring managers or teammates can clone and deploy in <15 min to evaluate modern DevOps practices. The completed project should demonstrate:

* Modern **service-mesh-ready** architecture
* **Automated, shift-left** security & quality gates
* **One-click** promotion from dev → staging → prod
* End-to-end **observability** and **cost transparency**

---

### 3 · Goals & Success Metrics

| Goal           | KPI / Acceptance                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| Spin-up speed  | `make dev-up` gives a working stack (gateway + ≥ 3 services + Postgres + Grafana) in ≤ 5 min on a 4-core laptop |
| CI reliability | 100 % automated checks on every PR (lint, unit, SCA, container scan, e2e) – pipeline time ≤ 10 min              |
| Deployment     | Push to `main` auto-deploys to a managed K8s sandbox (e.g., AKS) via GitHub Actions & Helm                      |
| Observability  | Request traces visible in Grafana Tempo; 90th-pct API latency charted                                           |
| Documentation  | README + diagrams let a new contributor install, code, test, and deploy inside 30 min                           |

### 5 · High-Level Architecture

```
┌────────────┐
│   Client   │
└─────┬──────┘
      │ HTTPS
┌─────▼──────┐
│ API-Gateway│  (Node + Fastify)
└──┬──┬──┬───┘
   │  │  │ gRPC / REST
┌──▼┐┌▼─┐┌▼─┐
│Auth│User│Orders│  (Go / TS Services)
└─┬─┘└┬─┘└─┬─┘
  SQL  SQL  SQL
   └────┬────┘
      Postgres
```

*Sidecars*: OpenTelemetry collector + Envoy proxy per pod
*Platform*: GitHub → DockerHub registry → AKS (dev/stage/prod namespaces)

### 6 · Functional Requirements

| #    | Requirement                                                                                                                                                               | Notes                                                  |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| F-01 | **API Gateway routing** with JWT auth & rate-limit                                                                                                                        | Leverage `fastify-rate-limit`                          |
| F-02 | **Auth Service**<br>• `/signup`, `/login` (bcrypt + JWT)<br>• `/refresh` token                                                                                            | 201/200/4xx responses                                  |
| F-03 | **User Service** CRUD                                                                                                                                                     | REST + OpenAPI-3 spec                                  |
| F-04 | **Orders Service** create/read                                                                                                                                            | Demo async outbox event (Kafka or NATS)                |
| F-05 | **Service discovery** via K8s cluster DNS                                                                                                                                 | Gateway uses service DNS                               |
| F-06 | **Centralised logging**                                                                                                                                                   | Std-out to Loki; query via Grafana                     |
| F-07 | **Metrics & tracing**                                                                                                                                                     | Prom-scraped `/metrics`; OTLP traces                   |
| F-08 | **CI Pipeline** stages<br>1) Install → Lint → Unit tests<br>2) Build multi-arch Docker (arm64/amd64)<br>3) Trivy scan<br>4) Push to registry<br>5) Helm upgrade --install | Fail-fast pattern                                      |
| F-09 | **Blue-green deploy** for prod                                                                                                                                            | Two AKS deployments + routed by Stable/Preview service |
| F-10 | **Automated database migration**                                                                                                                                          | `golang-migrate` job run as init-container             |

### 10 · CI/CD Pipeline Detail

```yaml
name: CI
on:
  pull_request:
  push: { branches: [main] }

jobs:
  test:
    runs-on: ubuntu-latest
    steps: [checkout, setup-node, npm ci, npm run lint, npm test]
  build:
    needs: test
    strategy: { matrix: { arch: [amd64, arm64] } }
    steps: [buildx bake, trivy scan, push]
  deploy:
    needs: build
    if: github.ref == 'refs/heads/main'
    steps: [helm upgrade --install]
```
